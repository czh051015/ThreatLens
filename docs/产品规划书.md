# ThreatLens 产品规划书

> 文档类型：产品规划 / 路线图
> 版本：v0.3（2026-09-01：P1/P2 完成，指标实测落地——precision 57.1% / recall 100%）
> 关联文档：`docs/开发说明/01-数据准备.md`、`docs/dev-spec.md`（单智能体 IoC 研判开发说明书）

## 0. 一句话定位

**ThreatLens 是一个 EDR 攻击链分析引擎（产品主干）**：输入主机遥测（Sysmon 事件流），输出"用了哪些 ATT&CK 技术 + 完整攻击链 + 可解释证据链"。

原规划中的"IoC 威胁情报研判"（A 线）降级为 **延后扩展模块**：待 MVP 跑通、且有 API key 后再做。

> 这个定位是 2026-08-31 grill 中由用户拍板确定：B（EDR 攻击链）= MVP 主干，A（IoC 富集）= 延后 stretch。理由见 §1。

---

## 1. 为什么是这个定位（决策依据）

| 决策点 | 结论 | 依据 |
|---|---|---|
| 产品主干选 B 还是 A | **选 B（EDR 攻击链）** | 联软科技 = 终端安全 / EDR 厂商，B 正是其主场；A 是通用 SOC 能力，不贴领域 |
| A 是否进 MVP | **否，延后** | ① A 已被开源覆盖（IntelOwl / ioc-threat-intel），commoditized，无稀缺性；② A 的 eval 数据当前是纸面（Abuse.ch 仅验证端点可达、从未落盘） |
| 与实习经历的衔接 | **贴 B 走** | 用户在联软"只用过、没搭过" EDR 系统；B 直接补上"能工程化搭建攻击链分析链路"的缺口 |
| 诚实红线 | **原型 ≠ 联软生产系统** | ThreatLens 是个人原型，话术须真实，绝不可谎称"在联软搭建了 EDR 系统" |

**B 与 A 的关系（消除"两条线"困惑）**：B 是"主机内部做了什么"（行为分析），A 是"攻击链里提取出的指标在全球范围是否已知恶意"（外部声誉）。真实 EDR 调查里，分析师先由 B 看到可疑进程、提取出 C2 IP，再用 A 去威胁情报平台佐证——**A 是 B 分析链路末端"提取 IoC → 外部富集"那一步**，而非独立产品。

## 2. 阶段划分

```
P0 数据基座(✓) ──► P1 分析Agent(MVP核心) ──► P2 eval证明(差异化证据)
                         │
                         └──(延后)──► P3 IoC富集(A) ──► P4 可集成/生态(延后)
```

### P0 · 数据基座 —— 已完成 ✓
- **目标**：备齐四源真实数据，作为后续所有分析的弹药库。
- **交付**：`edr/data/{attack,telemetry,atomic,sigma}/` 四源落盘。
  - attack：ATT&CK Enterprise STIX（858 技术）
  - telemetry：Mordor 多阶段真实遥测（mimikatz 凭据访问 + empire_launcher 执行 + seatbelt 发现 + covenant SMB 横向移动，JSONL）
  - atomic：Atomic Red Team（344 技术目录，含 Txxxx.md/.yaml）
  - sigma：Sigma windows 规则（2410 条 .yml，带 `attack.t*` 标签）
- **验收**：四源均能从本地加载（不依赖外网）。

### P1 · 分析 Agent（多智能体架构中的分析节点，MVP 核心）—— 已完成 ✓
- **目标**：实现**分析 Agent**的"事件流 → ATT&CK 技术 → 攻击链"确定性主干，LLM 仅做解释层。
- **交付**：
  1. 归一化事件 schema（`01-数据准备.md` §7，10 字段共同契约）
  2. Sigma×ATT&CK 映射引擎（确定性脚本查表，非 LLM）
  3. 攻击链重建（序列关联 → technique → chain）
  4. LLM 仅解释层（介入点①低分证据复核 ✓、②冲突证据裁决 ✓，见 04；介入点③**报告解释 ⬜ 待补**；模糊输入解析归 P3 IoC 能力）
- **验收**：用**拼接的多阶段 Mordor 遥测**跑通"事件 → 多 ATT&CK 技术 → 完整攻击链"；MVP demo 至少覆盖 **Execution / Credential Access / Discovery / Lateral Movement** 四阶段（mimikatz 为已有样本，另补 execution / discovery / lateral_movement 数据集）。
- **数据依赖**：P0 四源。

### P2 · eval 证明（差异化证据）
- **目标**：用真实金标跑出"可复现的真指标"，证明 Agent 架构（规则主干+LLM 解释）的价值。
- **交付**：
  1. 确定性 baseline（Sigma 规则 + ATT&CK 字典查表，全程无 LLM）
  2. +LLM 版（同链路 + LLM 解释层）
  3. 两版跑同一 Mordor+Atomic 金标，产出对比表
- **验收（目标值先摸底后定）**：
  - **第一步：先跑确定性 baseline**（Sigma 规则 + ATT&CK 字典查表，全程无 LLM），记录 baseline 自身的"技术识别准确率 / 链还原完整度"。
  - **目标值不预先锁死**：以 baseline 实测为锚点——若 baseline 已很高（如 ≥85%），说明规则查表已接近天花板，LLM 层增量有限，卖点 pivot 到"可解释性 + 冲突推理 + 证据链可追溯"（见 §4）；若 baseline 偏低，则"Agent 优于脚本"故事成立，目标值按 baseline 上浮设定。
  - **P2 实测落地（2026-09-01）**：技术识别 **precision 36.4% → 44.4% → 57.1%**（低分复核 + 冲突裁决两轮 LLM 介入），**recall 与阶段召回 100% 全程保持**；版本分离评测 + prompt 防背答案 + 快照制历史对比，连跑两遍逐字节一致，100 测试全绿。baseline 摸底方法论已实证：先测 baseline（36.4%）再按上浮迭代，未预锁 85/70。
- **数据依赖**：P0 四源 + P1 内核。
- **简历价值**：这两项指标是跑得出来、能复现的真数，非编造。

### P3 · IoC 富集模块（延后 / stretch）
- **目标**：从攻击链提取 IoC（IP/域名/hash）→ VT/OTX/Abuse.ch 富集，补"外部声誉佐证"。
- **前置条件（必须满足才启动）**：
  1. 真实下载 Abuse.ch 数据到本地（当前仅端点验证，eval 为纸面）
  2. 用户确认要做"完整闭环"话术、且具备 VT/OTX/AbuseIPDB 的 API key
- **验收**：攻击链报告里每个外连指标带外部声誉标注（如"该 IP 为 Feodo 标注的 Emotet C2"）。

### P4 · 可集成 / 生态（延后 / stretch）
- **目标**：暴露 MCP 工具壳 `lens_*`，让外部 client 可调用；整理联软生态接入话术。
- **诚实边界**：MCP 壳须真实可跑；联软生态接入标注"规划中 / 商务对接"，**不谎称已实现**。
- **验收**：本地 MCP server 能被外部 client 调用并返回结构化结果。

## 4. 风险与诚实边界

- **🚫 简历话术红线**：只能讲"在联软实习积累了 EDR/ATT&CK 领域认知，独立搭建 ThreatLens 原型复现攻击链分析链路"；**不可讲"在联软搭建了 EDR 系统"**。
- **⚠️ P2 生死线**：若 P2 跑出 LLM 层相比纯规则 baseline 无量化提升，卖点从"Agent 比脚本强"切到"可解释性 + 冲突推理 + 证据链可追溯"（这三个是规则聚合做不到、LLM 真有价值的支点）。
- **⚠️ A 纸面风险**：P3 启动前若不先落 Abuse.ch 真实数据，A 的 eval 仍是纸面，简历不可写。
- **⚠️ 网络环境**：国内拉取 GitHub 需直连 `raw.githubusercontent.com`（ghproxy 镜像实测失效）。
