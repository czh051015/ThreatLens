## 1. 决策摘要（TL;DR）

- **产品主干 = EDR 攻击链分析引擎（线 B）**：输入主机遥测（Sysmon 事件流），输出"用了哪些 ATT&CK 技术 + 完整攻击链 + 可解释证据链"。
- **IoC 研判（线 A）= 延后至 P3 的扩展模块**，不进 MVP 分析内核。
- **多智能体闭环（采集→分析→处置→报告）= 愿景北极星**；MVP 先落**分析 Agent**，采集/报告 Agent 随 MVP，自动处置 Agent 因安全与可演示性列 Non-goals。
- **MVP 用完整攻击链（≥3 阶段）**，而非单步 mimikatz。
- **P2 先跑 Sigma baseline 摸底，再按 baseline 上浮定目标值**，不预锁 85%/70%。
- **压力测试结论被采纳为"尺子误用"**：Weak verdict 针对"创业产品"不成立，作品集叙事需改写。
- **诚实红线**：原型 ≠ 联软系统，话术只能讲"实习积累认知 + 独立搭建原型"。

---

## 2. 背景与问题

项目最初定位摇摆于两条线：

- **线 A · IoC 研判**：输入一个指标（hash/IP/域名/URL）→ 多源查表融合 → verdict。已被开源（IntelOwl、ioc-threat-intel）commoditized。
- **线 B · EDR 事件流分析**：输入 Sysmon 事件流 → 序列关联 + Sigma×ATT&CK 映射 → 攻击链还原。

用户实习背景为**联软科技（终端安全/EDR 厂商）AI 开发实习生**，自述"只用过系统、没搭建过"。核心诉求是**把项目融进实习经历**。
由此引发关键判断：线 B 正是联软的产品领域，且能补上"用过没搭过"的能力缺口；线 A 既被开源覆盖、又与联软关联弱。

---

## 3. 决策内容

### 3.1 主线定位
| 项 | 决策 |
|---|---|
| 产品主干 | **线 B：EDR 攻击链分析引擎**（MVP） |
| IoC 研判 | **线 A：延后至 P3**，作为分析链路内的 enrichment 子模块，不在 MVP 内核 |
| 多智能体 | 愿景北极星；MVP 先落**分析 Agent**，采集/报告 Agent 随 MVP，处置 Agent 列 Non-goals |

> 依据：线 A 的 eval 真值当时为纸面（`seeds.json` 硬编码示例，Abuse.ch 未落盘），线 B 数据已真实落盘（Mordor/ATT&CK/Atomic/Sigma 四源实测可下载）。

### 3.2 MVP 范围（grill Q1=a）
- 采用 **4 阶段 demo 链**：Execution → Credential Access → Discovery → Lateral Movement。
- 已实拉数据集：
  - `empire_launcher_vbs`（Execution，2067 事件）
  - `empire_mimikatz_logonpasswords`（Credential Access，6026 事件）
  - `cmd_seatbelt_group_user`（Discovery，451 事件）
  - `covenant_copy_smb_CreateRequest`（Lateral Movement，506 事件）
- 理由：简历话术"攻击链还原完整度 Y%"必须有**多阶段链**支撑，单步 mimikatz 撑不起"链"字。

### 3.3 评测策略（grill Q2）
- P2 先跑**纯 Sigma 规则 baseline**（Sigma 查表 + ATT&CK 字典，全程无 LLM）。
- baseline 低 → LLM 有空间，主叙事成立；baseline 已高 → pivot 到"可解释性/冲突推理/证据链可追溯"。
- **不预锁 85%/70% 硬指标**，先摸底再定目标值。

## 4. 压力测试复盘（startup-pressure-test）

| 项 | 内容 |
|---|---|
| 工具 | `$startup-pressure-test`（full 模式），用"EDR 攻击链分析引擎"为命题 |
| Verdict | **Weak → 需要 pivot**（Pain 4/5，但 Buyer/Urgency/Differentiation/Founder 均 2/5） |
| 核心判词 | "攻击链分析"已被 CrowdStrike(IOA/Attack Chain)、SentinelOne(Storyline)、MS Defender XDR(Attack Story + Copilot)、Elastic(Attack Discovery) 做成 EDR 原生功能；独立引擎是巨头路线图上的一个 feature |
| Fatal Flaws | ① 被 EDR 原生功能吸收（High）；② 拿不到真实客户数据=没产品（High）；③ 信任/评估无底洞（Medium） |

### 4.1 为什么该 Verdict 不适用于本项目
1. **尺子用错**：测试用"独立商业产品市场存活率"度量一个**秋招作品集**，维度（Buyer clarity / Urgency / Founder advantage）本身不适用。
2. **两点真正戳中、且已被现有设计化解**：
   - "别拼链画得好" → 印证主叙事应拼"**工程方法证明 Agent 比脚本强**"（混合架构 + eval 量化），而非与巨头比可视化。
   - "拿不到数据=没产品" → 本项目用 **Mordor 公开标注遥测当输入、ATT&CK/Atomic 当金标**，不依赖真实客户数据，且能跑出 precision/recall 真指标，fatal flaw 不成立。

### 4.2 采纳的叙事改写
- 从"我做了攻击链分析**产品**" → "我**逆向复现**了实习中操作的 EDR 分析链路，并用工程方法证明混合架构优于纯脚本"。
- 简历锚定"**用过 → 能搭**"的能力跃迁；继续弱化"30 秒/4 源"等易被追问的指标。

## 5. 竞品与差异化主张（来自竞品分析）

- 企业级 Agentic SOC（CrowdStrike Charlotte AI、MS Security Copilot、Simbian 等）：做"全 SOC"，本项目只做"情报/攻击链研判"子集。
- 开源 IoC 富集（ioc-threat-intel、IntelOwl）：与线 A 高度重合，commoditized；进一步佐证 A 延后。
- **本项目差异化支点**：开源工具全是"脚本思维"；本项目的**混合架构决策 + eval 量化证明 + 冲突推理**是开源没做的，对应面试官想看的"工程判断力"。

---

## 6. 诚实红线（必须守住）

- ThreatLens 是**个人原型**，不是联软的系统；用户也未在实习中搭建过生产级 EDR。
- ✅ 可讲："在联软实习期间积累 EDR/ATT&CK 领域认知，独立搭建 ThreatLens 原型，证明我能工程化实现此前只操作过的攻击链分析链路。"
- ❌ 绝不可讲："我在联软搭建了 EDR 分析系统"（造假，一问即穿）。
- 联软生态 MCP 接入若做不到真实接入，只能标注"规划中/商务对接"，不可称已实现。
