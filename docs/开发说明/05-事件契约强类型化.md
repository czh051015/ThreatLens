## 1. 背景与目标（Why）

### 1.1 两个动机

**工程动机（真实价值）**：本项目踩过字段错配类 bug——`_CONTEXT_FIELDS` 用 Sigma 大写字段名、事件模型却是小写蛇形，导致 LLM 首跑看不到证据全部判 unknown（04 交付时修复）。这类"字段名/类型不一致"问题在自由 dict 结构下只能在运行时踩到才暴露；强类型 Schema 能在**加载期**就拦截。

**求职动机**：目标岗位为 AI 应用开发，Pydantic v2 强类型 Schema + Field Validation 是该方向的核心技能展示（业界 Agent 工程标配：数据契约、LLM 输出校验）。

### 1.2 目标
- 用 **Pydantic v2** 为 `NormalizedEvent`（01 §7 十字段 + `event_uid`）建立强类型模型 + Field Validation；
- 9050 条真实事件**无损通过校验（0 丢行）**；
- **下游零改动**：sigma_matcher / chain_builder / run_eval / run_eval_agent / demo 全部不修改、测试全绿；
- 简历技术栈可写：**Pydantic v2 强类型事件 Schema + Field Validation**。

## 2. 范围（Scope & Non-goals）

**In scope**
- `threatlens/core/data/load_telemetry.py` 改造（输出经 Pydantic 验证）。
- `requirements.txt` 增加 `pydantic>=2.0`。
- 新增 `NormalizedEvent` 模型（放 `threatlens/core/data/schema.py` 或 load_telemetry 内）。
- 01 §7 文档同步（标注"已由 Pydantic v2 强制校验"）。
- 简历技术栈补 Pydantic v2；新增测试。

**Non-goals**
- **不改其他 loader**：Sigma/ATT&CK/Atomic 保持现有 yaml/json 解析，不强类型化。
- **不改匹配/链重建/评测**：输出结构保持 dict 兼容，下游零改动。
- 不做性能优化（9050 行验证开销可忽略，不做基准）。
- 不引入 Pydantic 到 LLM 复核输出（verdict JSON 解析保持现有实现，另议）。

## 3. 设计

### 3.1 NormalizedEvent 模型（10 + 1 字段）

| 字段 | 类型 | 校验规则 | 来源 |
|---|---|---|---|
| `event_uid` | str | 非空；匹配 `^.+\.json:\d+$`（文件名:行号） | 生成（02 §5.1） |
| `event_id` | int | 0–65535（Windows 事件 ID 范围） | `EventID` / `event_id` |
| `timestamp` | str | 可解析为 ISO8601 UTC（含 Z/偏移）；解析失败报错 | `@timestamp` / `EventTime` |
| `host` | str \| None | — | `Hostname` / `host` |
| `process_name` | str \| None | — | `Image` / `process_name` |
| `process_id` | int \| None | ≥ 0 | `ProcessId` / `process_id` |
| `parent_process` | str \| None | — | `ParentImage` / `parent_image` |
| `command_line` | str \| None | — | `CommandLine` / `command_line` |
| `user` | str \| None | — | `User` / `user` |
| `tactic_hint` | str \| None | 仅线索非金标 | 数据集级标注 |
| `raw` | dict | 非空 dict | 整条原始 JSON |

> 字段语义完全对齐 01 §7；`timestamp` 校验复用现有 `_to_iso_utc`（失败即 `ValidationError`，不再静默 None——这是对旧行为"解析失败返回 None"的收紧，正是本次改造的价值）。

### 3.2 兼容策略（下游零改动的关键）

```
load_telemetry_events(path) -> list[dict]
  ├─ 逐行 json.loads（现有逻辑不变）
  ├─ NormalizedEvent(**event)   ← Pydantic 构造触发校验（失败抛 ValidationError 并带行号）
  ├─ .model_dump()              ← 转回 dict（结构与现有一致）
  └─ 返回 list[dict]            ← 下游 100% 兼容，零改动
```

- **签名不变**：`load_telemetry_events(path) -> list[dict]`，所有调用方无需修改。
- 模型类同时暴露（`from threatlens.core.data import NormalizedEvent`），供类型提示与未来重构使用。
- 校验失败：抛出带行号的 `ValueError("line 42: ...")`，**fail-fast**——因为验收要求 9050 行全部合法，任何失败都是真实 bug，不该静默跳过。

### 3.3 校验失败处理
- fail-fast：抛错并报告 `数据集文件名:行号` 与原始字段，便于定位。
- 验收用 9050 行真实数据证明"0 失败"；新增单测覆盖非法样本（event_uid 格式错、timestamp 非法、event_id 越界）各抛错。

## 5. 实现指引

1. `pip install "pydantic>=2.0"`（写入 requirements.txt）。
2. 新建 `threatlens/core/data/schema.py`：`NormalizedEvent(BaseModel)` + 字段校验（§3.1 表），`field_validator` 处理 timestamp/event_uid。
3. 改 `load_telemetry.py`：构造事件 dict → `NormalizedEvent(**ev)` → `model_dump()`；try/except 捕获 `ValidationError` 转带行号 ValueError。
4. 新增 `tests/test_normalized_schema.py`：合法 9050 行 + 非法样本断言。
5. 跑全量测试（96+新）+ 重跑 demo/评测验证指标不变。
6. 更新 01 §7 文档标注 + 简历技术栈。

## 6. 风险与约束

| 风险 | 说明 / 缓解 |
|---|---|
| 下游破坏 | 兼容策略（§3.2）dict 输出 + 全量测试兜底，指标复现验证 |
| timestamp 收紧导致丢行 | 旧代码对失败行返回 None（静默）；新代码抛错。9050 行实测通过即无此问题；若有失败行按 §3.3 定位修复 |
| Pydantic v2 API 不熟 | 只用 `BaseModel` + `field_validator` 最小子集，参照官方文档 |
| 简历夸大 | 只有代码真改完 + 测试绿，才更新简历技术栈 |
