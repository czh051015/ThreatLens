## 1. 背景与目标（Why）

承接规划书 **P1 · 分析 Agent（MVP 核心）**：把 01 准备好的数据基座变成产品能力——

> 输入：Mordor 真实遥测（4 数据集 JSONL）→ 输出：**用了哪些 ATT&CK 技术 + 完整攻击链 + 可解释证据链**。

本说明书解决"从**能读数据**（01 完成）到**能出攻击链**（本说明书）"中间的分析链路。

**主线原则（与 01 §1 一致）**：主干 100% 确定性——Sigma 查表 + ATT&CK 字典 + 时间线排序，**全程无 LLM**；LLM 仅解释层（P2 叠加）。

---

## 2. 范围（Scope & Non-goals）

**In scope**
- 正向匹配引擎 `sigma_matcher`（事件 → 候选技术 + 证据三元组）。
- 链重建 `chain_builder`（打分去噪 + 两层时间线 + 攻击链输出）。
- 金标 loader `load_atomic`（已知技术列表，供 P2 eval 对照）。
- `event_uid` 事件唯一标识约定（01 §7 扩展，本说明书 §5.1）。

**Non-goals（明确不做）**
- 不接 LLM（P2 才叠解释层，且不参与判定主干）。
- 不做 IoC 富集（P3 延后模块）。
- 不做自动处置（规划书 Non-goals）。
- **不实现完整 Sigma 语法**：MVP 支持 **Sigma-lite 子集**——字段修饰符 `eq`/`contains`/`endswith`（任意字段）+ 条件结构 `selection` / `1 of` / `all of` / `or` / `and` / `not`。完整 Sigma 语法（`|re` / `|startswith` / 聚合 / 字段变换等）留待迭代。
- **自写 1 条确定性规则**为 demo 链补齐 T1003.001（mimikatz 数据集官方规则无法命中，详见 §5.6）——基于真实数据 + ATT&CK 知识，仍是确定性规则非 LLM。

## 5. 关键设计决策（含真实坑）

### 5.1 ⚠️ `event_id` ≠ 事件唯一 ID（写代码前必须知道）
- **坑**：§7 的 `event_id` 是 **Windows 事件类型号**（1/10/3…），不是事件唯一标识——6026 条事件里几百条都是 `event_id=10`。
- **后果**：evidence 若用 `event_id` 引用事件，无法区分具体哪一条，回溯全乱，P2 无法核对。
- **约定**：每条事件生成 `event_uid = f"{数据集文件名}:{行号}"`（跨数据集唯一、稳定、可逆查回 raw）。
  - 在 `load_telemetry.py` 内生成（用户确认），不改调用方签名。
  - evidence 一律引用 `event_uid`，**禁止**用 `event_id`。

### 5.2 反向索引 + 正向匹配两层（不重复劳动）
| 层 | 模块 | 方向 | 用途 |
|---|---|---|---|
| 反向索引 | `load_sigma` | 技术 → 规则 | 构建期预解析；运行期按 `event_id` 缩小候选；P2 算规则覆盖度 |
| 正向匹配 | `sigma_matcher` | 事件 → 规则条件 → 技术 | **运行时主链路**：拿事件字段逐条比对 `detection` |

> 正向匹配借用反向索引加速：先按事件的 `event_id` 取候选规则子集（2410 条 → 几十条），再比对条件。

**Sigma-lite 支持范围**（实测覆盖 4 阶段 demo 链）：
- **字段修饰符**：`eq` / `contains` / `endswith`（任意字段，如 `EventID` / `CommandLine` / `SourceImage` / `TargetImage` / `ShareName` / `AccessMask`）。
- **条件结构**：`selection` / `1 of selection_name` / `all of selection_name` / `or` / `and` / `not`。
- **不**支持：`|re` / `|startswith` / `|base64` / 近重复 / 聚合（`count` / `sum`）/ 字段变换。

> 实测覆盖：T1059.001（contains）/ T1087（endswith）/ T1021.002（endswith + 字段组合）+ 自写 T1003.001（endswith）—— 4 阶段全通。

### 5.3 两层时间线（跨数据集日期不可比）
- **数据集内**：按 `timestamp` 排序（真实先后，可靠）。
- **数据集间**：按**战术阶段顺序**排（Execution → Credential Access → Discovery → Lateral Movement，demo 链定义）。
- 原因：4 个数据集是不同日期的独立模拟（2020-08/09/09/11），全局按时间排会得到"假顺序"。

### 5.4 去噪打分（降权优先于硬删）
`score_event()` 分层规则：

| 层级 | 规则 | 示例 |
|---|---|---|
| 硬排除（score=0） | 系统引导进程自身创建事件 | `System`、`smss.exe`、`csrss.exe`、`wininit.exe` |
| 降权（×0.3） | 常见系统进程行为 | `svchost.exe` 自身执行、`lsass.exe` 常规启动 |
| 提权（+2） | 攻击载荷特征 | 命令行含 `mimikatz`/`-ma lsass`/base64/`-enc`；从 `%TEMP%`、`AppData` 启动 |
| 谱系（±1） | 父进程链异常 | 父进程为 `wscript`/`powershell` → 加分；父链全系统服务 → 降权 |
| 聚合去重 | 同技术命中多事件只留 top-K | 每技术最多挂 5 条最高分证据 |

> 分数低于阈值的命中**不参与链重建**；证据列表按分数排序。

### 5.5 证据三元组（evidence 的天然来源）
- 匹配命中即产生：`{technique_id ← rule_path ← event_uid}`，累积为证据链。
- **evidence 不是额外数据，是匹配过程的副产品**——可解释性由此而来。

### 5.6 自定义规则（custom rules）—— 为 demo 链补齐 T1003.001
- **问题**：mimikatz 数据集无 `mimikatz` 关键字；唯一攻击事件是 line 2451 `powershell.exe → lsass.exe`（AccessMask `0x1010`）。官方 lsass 规则把 `0x1010` 注释为误报排除（现实攻击太杂），导致严格按官方规则 T1003.001 命不中。
- **方案**：在 `threatlens/core/analysis/sigma_custom_rules/` 下自写 1 条确定性规则 `credentials_access_powershell_lsass.yml`，逻辑：powershell 进程访问 lsass（`SourceImage|endswith: \powershell.exe` + `TargetImage|endswith: \lsass.exe`）。基于真实数据特征 + ATT&CK T1003.001 知识，**零误报**（数据集内仅 line 2451 一条命中）。
- **为何不算 LLM**：规则 YAML 由人手写、`detection` 条件纯确定性匹配，与官方 Sigma 规则性质一致；只是规则作者不是 OTRF/SigmaHQ。
- **加载方式**：`sigma_matcher` 加载规则时合并两个根——官方 `edr/data/sigma/_src/rules/windows/` + 自定义 `threatlens/core/analysis/sigma_custom_rules/`，合并为同一规则集。
- **扩展性**：后续若需补其他 demo 阶段（如 C2），可按同样模式追加自定义规则，放同一目录。

**自定义规则 YAML 示例（`credentials_access_powershell_lsass.yml`）**：

```yaml
title: PowerShell accessing LSASS memory (T1003.001)
id: custom-powershell-lsass-access
status: experimental
description: Custom rule for ThreatLens demo — PowerShell opening LSASS process memory for credential dumping. Zero FP on mimikatz dataset (line 2451 only).
author: threatlens
date: 2026-08-31
tags:
  - attack.credential-access
  - attack.t1003.001
logsource:
  product: windows
  category: process_access
detection:
  selection:
    SourceImage|endswith: '\powershell.exe'
    TargetImage|endswith: '\lsass.exe'
  condition: selection
falsepositives:
  - none observed in mimikatz dataset (line 2451 zero false-positive)
level: high
```

### 5.7 战术名标准化（数据源修正，2026-08-31 实测）
- `enterprise-attack.json` 数据源含非标准战术名：`stealth`×212、`defense-impairment`×56（ATT&CK 标准应为 `defense-evasion` 等）。`load_attack.py` 以 `TACTIC_ALIASES` 映射回标准名（`stealth`/`defense-impairment` → `defense-evasion`），保证 P2 战术统计口径正确。
- 非代码 bug，是 STIX 数据源问题；依据见 `ADR-003` §3.7，代码已生效（demo 输出 6 个标准战术）。

## 6. 数据结构

### 6.1 NormalizedEvent（01 §7 扩展）
```python
{
  "event_uid": "empire_mimikatz_logonpasswords_....json:42",  # 新增，见 §5.1
  "event_id": 10, "timestamp": "2020-08-07T14:32:25.358000Z",
  "host": "...", "process_name": "...", "process_id": 123,
  "parent_process": "...", "command_line": "...", "user": "...",
  "tactic_hint": None, "raw": {...},
}
```

### 6.2 MatchResult（三元组）
```python
@dataclass
class MatchResult:
    event_uid: str          # 哪条事件
    rule_path: str          # 命中哪条规则
    technique_id: str       # 规则 tags 里的 attack.tXXXX
    matched: dict           # 命中的字段条件，如 {"EventID": 10}
```

### 6.3 AttackChain（报告输出结构，P2 eval 直接消费）
```json
{
  "chain": [
    {"tactic": "execution",           "technique": "T1059.001",
     "first_seen": "2020-09-04T20:09:40Z", "evidence": ["launcher_vbs.json:88", "..."]},
    {"tactic": "credential-access",   "technique": "T1003.001",
     "first_seen": "...", "evidence": ["mimikatz.json:1024", "..."]}
  ],
  "techniques": {"T1059.001": {"name": "Command and Scripting Interpreter", "tactics": ["execution"]}},
  "summary": "共识别 N 个技术，覆盖 4 个战术阶段"
}
```

## 7. 评测接口（P2 前置，本说明书先钉死）

- **技术识别准确率**：`chain.techniques` 的键集 vs `load_atomic` 金标技术集 → precision / recall。
- **链还原完整度**：`chain.chain` 覆盖的阶段数 / 金标阶段数（Atomic 链定义）。
- **可回溯性验收**：链上每个 `technique` 的 `evidence` 非空，且每条 evidence 能通过 `event_uid` 反查 `raw`。
- 输出统一为 `AttackChain` JSON，两版（baseline 规则版 / baseline+LLM 版）跑同一结构，P2 直接对比。
