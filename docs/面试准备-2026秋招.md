# 面试准备材料（ThreatLens 项目版）

> 用途：秋招 AI 应用开发岗，把 ThreatLens 项目"讲给面试官听"的准备材料。
> 对应简历：`docs/简历-2026秋招.md`。数字全部来自真实评测（2026-08-31 ~ 09-01）。

---

## 1. 一分钟自我介绍（开场背熟）

> 我在联软科技做过 AI 开发实习生，接触了 EDR 终端安全产品的实际运作，了解了 MITRE ATT&CK 攻击框架。
> 实习期间发现自己只会用系统、不会搭系统，所以回来独立做了一个项目叫 ThreatLens：
> 输入主机遥测事件（Sysmon 日志），输出"用了哪些攻击技术 + 完整攻击链 + 证据"。
> 做法是：Sigma 规则做确定性匹配（不依赖 LLM），LLM 只在三个明确的地方介入——低分证据复核、冲突裁决、报告解释。
> 用真实攻击数据（Mordor）评测：precision 从 36.4% 提到 57.1%，recall 一直保持 100%，所有数字可复现。
> 这个项目证明：我能把实习里只理解过的攻击链分析，真正工程化实现出来。

## 2. 面试官可能问的问题 + 怎么答

### Q1 介绍一下你的项目
- 一分钟版本（上面那段）。
- 展开讲架构 4 步：① 事件归一化（统一格式 + Pydantic 校验）→ ② 技术识别（Sigma 规则匹配 + ATT&CK 字典）→ ③ 链重建（两层时间线 + 去噪打分）→ ④ 报告输出（LLM 生成 + 证据）。
- 强调：主干全程确定性，LLM 只在三个点介入。

### Q2 和 CrowdStrike / SentinelOne 这些厂商比，你强在哪？
- 他们是商业产品，卖的是**结论**（黑盒）；我做的是**证明结论可以验证**：
  - 输入输出格式公开（JSONL 进、AttackChain 出）；
  - 评测可复现（同一条命令连跑两遍，输出逐字节一致）；
  - 证据能回溯到原始事件（每个技术挂 event_uid）。
- 一句话：**他们卖结论，我证明结论可验证。**

### Q3 为什么不用开源方案（IntelOwl / ioc-threat-intel）？
- 那些是脚本工具：多源查一下、打个分，就结束了。
- 我做的多两层：一是"怎么判"（规则主干 + 证据分层），二是"怎么证明判得对"（金标评测 + 版本分离）。
- 开源工具没有评测，我说我有数字。

### Q4 precision 为什么才 57.1%？不高啊
- 诚实说：precision 低的原因有两个——① 规则在真实数据上会误报；② 识别出的技术里有些是真实攻击行为，但不在我们这 4 个金标技术里。
- 重点：**recall 100%**——该抓的攻击技术全抓到了。
- 而且 precision 从 36.4% 提到 57.1%，靠的是 LLM 低分复核 + 冲突裁决——这正是"Agent 比脚本强"的证据。

### Q5 你的自定义规则是不是作弊？
- 不是，证据：评测分两个版本报告——官方规则版（36.4%）和官方+自定义版，**两个版本都公开**。
- 自定义规则的作用不是"提高 recall"（官方版 recall 也 100%，通过 security-audit 事件命中的），而是补一条标准证据。
- 防作弊的另一层：LLM 的 prompt 里禁止写测试集结论（防止背答案），这条写进了验收标准。

### Q6 为什么不用 embedding / 向量检索？
- 我的场景是**确定性规则匹配**（EventID=1、命令行包含某串），不需要语义相似度。
- embedding 适合"语义相似"的检索场景（比如找类似案例、从资料库召回），那是另一个项目（茅台 RAG 用 Chroma）。
- 在这个场景用 embedding 反而破坏可复现性（向量检索结果不绝对）。
- 能讲清"什么时候用、什么时候不用"，比都会用更值钱。

### Q7 为什么不做多 agent？
- ThreatLens 是封闭的确定性管道：事件进来、规则匹配、链重建、复核，每步输入输出是明确的。
- 多 agent 编排适合开放任务（情报调研、多轮检索、需要 Agent 自己规划工具调用）。
- 我的场景用 agent 自主编排反而破坏可复现性，所以 LLM 只限定在三个介入点。
- 这说明我知道多 agent 是什么、适合什么场景，不是不会做。

### Q8 LLM 结果能复现吗？
- 能：`temperature=0` + 每次调用输入输出落审计日志（jsonl）。
- mock 模式全确定性；真实 API 模式连跑两遍，评测指标逐字节一致（有 diff 验证）。

### Q9 怎么证明你的审计是对的？
- 三个数字：
  - 证据可回溯率 100%（34 条证据全部能反查回原始事件）；
  - 金标技术 0 误剔（冲突裁决的硬约束，代码强制）；
  - LLM 每次复核/裁决的输入输出都落日志，可人工核对。

### Q10 数据是真实吗？
- 是，全部公开数据集：Mordor（微软研究员录的真实攻击遥测）、Atomic Red Team（攻击技术金标）、Sigma（官方检测规则）、ATT&CK STIX（官方知识库）。
- 不是编的，下载命令在 README 里，谁都能复现。

### Q11 这个项目和实习经历什么关系？
- 实习让我理解了 ATT&CK 框架和 EDR 分析链路（用系统）。
- 项目是实习后独立做的原型（搭系统），证明"用过 → 能搭"。
- **注意**：项目是个人原型，不是联软的系统，绝不说"我在联软搭建了 EDR 系统"。

### Q12 实习里你做了什么？
- 参与 EDR 平台告警分析与日常运营，积累 ATT&CK 框架和终端检测链路的认知。
- 诚实：实习偏使用和运营，没有开发公司系统；ThreatLens 是我把实习理解的东西工程化。

### Q13 为什么主干不用 LLM？
- 确定性：同输入同输出，可复现、可测试、可审计。
- 成本：规则查表免费，LLM 只在真正需要判断的三个点调用。
- LLM 的作用是补规则的短板（低分误报、多标签冲突、报告可读），不是替代规则。

### Q14 你踩过什么坑？（技术细节展示）
- 条件解析把 `and`/`not` 吞进通配名 → 581 条假误报；
- `.strip()` 把反混淆用的空格剥掉 → 假报 whoami；
- Sigma 大写字段名 vs 事件模型蛇形字段 → LLM 首跑看不到证据全判 unknown；
- 审计日志路径写错一级（parents[4]）→ 写到项目外目录。
- 都是碰真实数据才踩的，都修了 + 加了回归测试。

## 3. 提醒清单（别说 / 别主动提）

| 事项 | 说明 |
|---|---|
| ❌ 绝不说"在联软搭建了 EDR 系统" | 造假，一问就穿。只能说"实习积累认知，独立搭建原型" |
| ⚠️ 说 57.1% 必须带上下文 | 带"recall 100%"和"基于 4 个金标技术"，否则显得样本小、数字低 |
| ⚠️ mock 和真实 API 分清 | 面试/简历用真实 API 版数字（57.1%）；mock 版（50%）只用于测试 |
| ⚠️ 报告解释层的真实状态 | 代码已实现、单测过了，但**真实 API 冒烟没跑过**。别吹"报告是 LLM 真实生成的"，说"真实调用逻辑已实现，测试覆盖幻觉剔除" |
| ⚠️ 别主动讲"30 秒出结果""4 个数据源" | 实现细节，容易被追问"为什么这么快""为什么只有 4 个" |
| ✅ 简历占位符记得填 | 姓名/电话/邮箱/学校/专业/实习时间 |
| ✅ 数据/代码可给链接 | GitHub 仓库 + README，面试官想验证就给 |

- 自我介绍背熟（1 分钟内）。
- Q1-Q14 每题先自己复述一遍，再对着镜子/录音练。

- 面试前把第 3 节提醒清单过一遍。
